A tree is a good way to represent the doctors because each doctor can report to another doctor, and each doctor can have up to two direct reports in this assignment. The top doctor is the root. The left and right links show who reports to each doctor. This makes the structure easy to follow and lets the program visit every doctor without storing one long flat list. In a real hospital, a manager might have more than two direct reports, but this assignment uses a binary tree to practice the basic idea.

The three traversals visit the same tree in different orders. Preorder visits a doctor before their reports, so it could make a simple top-down organization chart or report. Inorder visits the left side, doctor, then right side; it is useful in a binary search tree when values are arranged in order. Postorder visits the reports before the doctor, which can help when work should be completed from the bottom of a hierarchy upward, such as preparing a department summary after its teams are done.

A heap helps with emergency intake because staff can add a patient and quickly find the lowest urgency number. The program keeps the most urgent patient at the front, even when patients arrive in a different order. When someone is added or removed, the heap moves only the patients needed to restore its order. This makes it a useful model for a busy queue where priority matters. The code also returns None when the queue is empty, so checking or removing a patient does not cause an error.
